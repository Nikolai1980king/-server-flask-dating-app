```sql
CREATE TABLE chat_permission (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    sender_id VARCHAR NOT NULL,
    receiver_id VARCHAR NOT NULL,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    UNIQUE(sender_id, receiver_id)
```

## 🚀 Как это работает

### Сценарий 1: Первая отправка сюрприза

1. Пользователь **А** открывает `/visitors`
2. Видит кнопку ✨ "Удивить" у **ВСЕХ** посетителей
3. Нажимает на кнопку для пользователя **Б**
4. **Проверка статуса:** функция не оплачена
5. Открывается **модальное окно оплаты** (50₽)
6. Нажимает "Оплатить" → перенаправление на ЮKassa
7. Оплачивает → возврат на `/payment/success?type=surprise`
8. Сервер активирует функцию: `surprise_feature_paid = True`
9. Перенаправление на `/visitors?surprise_paid=1`
10. Показывается уведомление: "✨ Функция активирована!"
11. Теперь может нажать кнопку ✨ и **выбрать сюрприз**

### Сценарий 2: Отправка сюрприза после оплаты

1. Пользователь **А** (функция оплачена) нажимает ✨ для пользователя **Б**
2. **Проверка статуса:** функция оплачена ✅
3. Открывается модальное окно **выбора сюрприза**
4. Выбирает, например, 🍰 "Десерт"
5. Показывается анимация (для шампанского)
6. Сюрприз отправляется в чат
7. **Создается ChatPermission** (А → Б)
8. Уведомление: "🍰 Десерт отправлен! Теперь вы можете писать сообщения!"

### Сценарий 3: Общение после сюрприза

1. Пользователь **А** открывает "Мои сообщения" ✉️
2. В списке появился пользователь **Б** (благодаря ChatPermission)
3. Открывает чат с **Б**
4. Может писать сообщения **без мэтча**!
5. **Б** получает сообщения и может отвечать

## 📊 Схема логики доступа к чату

```
Чат доступен если:
├─ Есть Match (взаимный лайк)
│  └─ Оба могут писать сообщения
│
└─ Есть ChatPermission (отправлен сюрприз)
   ├─ Отправитель → может писать получателю
   └─ Получатель → может отвечать отправителю
```
