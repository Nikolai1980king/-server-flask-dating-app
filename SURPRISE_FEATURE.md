# ✨ Функция "Удивить" - Отправка сюрпризов посетителям

## 📋 Обзор

Добавлена новая функция **"Удивить"**, позволяющая отправлять собеседникам три типа сюрпризов:
1. 🍰 **Десерт** - красивое изображение десерта
2. 🍾 **Шампанское** - анимация с вылетающей пробкой
3. 😄 **Анекдот** - смешной анекдот про ресторан (без повторов)

## ✨ Возможности

### 1. Кнопка "Удивить"
- Появляется в карточке каждого посетителя на странице `/visitors`
- **Видна только при наличии мэтча** с этим пользователем
- Стильная круглая кнопка с эмодзи ✨ и градиентом
- Анимация при наведении (поворот и увеличение)

### 2. Модальное окно выбора
При нажатии на кнопку "Удивить" открывается красивое модальное окно с тремя вариантами:
- Каждый вариант представлен большим эмодзи и описанием
- Плавная анимация появления (fadeIn + slideUp)
- Hover-эффекты на каждой опции
- Закрытие по клику вне окна или на крестик

### 3. Десерт 🍰
- Отправляется специальное сообщение с маркером `SURPRISE_DESSERT`
- Получатель видит красивое изображение десерта в чате
- Мгновенная доставка через Socket.IO

### 4. Шампанское 🍾
- **Уникальная анимация вылета пробки!**
- При отправке показывается полноэкранная анимация:
  - Бутылка шампанского 🍾
  - Пробка вылетает с вращением (360° → 720°)
  - Искры и брызги ✨💫✨
  - Плавное исчезновение
- CSS keyframes анимация (1 секунда)
- Сообщение с маркером `SURPRISE_CHAMPAGNE` отправляется в чат

### 5. Анекдот 😄
- База из **25 смешных анекдотов** про рестораны и кафе
- **Система отслеживания повторов** - каждому пользователю анекдот отправляется только один раз
- Случайный выбор из доступных (не отправленных ранее) анекдотов
- Хранение истории в таблице `sent_joke`
- Уведомление, если все анекдоты уже отправлены

## 🗄️ База данных

### Новая таблица: `sent_joke`
```sql
CREATE TABLE sent_joke (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    sender_id VARCHAR NOT NULL,      -- Кто отправил
    receiver_id VARCHAR NOT NULL,    -- Кто получил
    joke_id INTEGER NOT NULL,        -- ID анекдота (индекс в массиве)
    sent_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    UNIQUE(sender_id, receiver_id, joke_id)
)
```

**Индексы для быстрого поиска:**
- `idx_sent_joke_sender` - по отправителю
- `idx_sent_joke_receiver` - по получателю
- `idx_sent_joke_pair` - по паре (отправитель-получатель)

## 🔧 Техническая реализация

### Backend

#### API Endpoint: `/api/send-surprise`
**Метод:** POST  
**Авторизация:** Требуется cookie `user_id`  
**Проверки:**
- Существование получателя
- Наличие мэтча между пользователями
- Для анекдотов - проверка на повторы

**Параметры запроса:**
```json
{
    "receiver_id": "uuid-получателя",
    "type": "dessert|champagne|joke"
}
```

**Ответ (успех):**
```json
{
    "success": true,
    "type": "dessert",
    "message": "Сюрприз успешно отправлен!"
}
```

**Ответ (все анекдоты отправлены):**
```json
{
    "error": "Все анекдоты уже отправлены этому пользователю",
    "all_jokes_sent": true
}
```

#### Модель: `SentJoke`
```python
class SentJoke(db.Model):
    id = db.Column(db.Integer, primary_key=True)
    sender_id = db.Column(db.String, nullable=False)
    receiver_id = db.Column(db.String, nullable=False)
    joke_id = db.Column(db.Integer, nullable=False)
    sent_at = db.Column(db.DateTime, default=datetime.utcnow)
```

#### Коллекция анекдотов: `RESTAURANT_JOKES`
Массив из 25 анекдотов про рестораны, официантов и кафе.

## 📊 Статистика

- **25 анекдотов** в базе
- **3 типа** сюрпризов
- **100% уникальность** - анекдоты не повторяются для каждого получателя
- **Мгновенная доставка** через Socket.IO
- **Красивая анимация** для шампанского (1 сек)

## 🐛 Обработка ошибок

### Ошибки, которые обрабатываются:
1. **Нет авторизации** - 401 Unauthorized
2. **Получатель не найден** - 404 Not Found
3. **Нет мэтча** - 403 Forbidden
4. **Все анекдоты отправлены** - 400 Bad Request (специальный флаг)
5. **Ошибка БД** - 500 Internal Server Error

### Пользовательские уведомления:
- ✅ Успех - зеленое уведомление
- ℹ️ Инфо - синее уведомление (все анекдоты отправлены)
- ❌ Ошибка - красное уведомление

## 🔐 Безопасность

### Проверки на backend:
1. Проверка авторизации (user_id в cookie)
2. Проверка существования получателя
3. **Обязательная проверка наличия мэтча** - сюрпризы можно отправлять только при мэтче
4. Уникальность (sender_id, receiver_id, joke_id) предотвращает дубликаты

### Проверки на frontend:
1. Кнопка видна только при мэтче (`{% if profile.id in matched_ids %}`)
2. Остановка события при клике (предотвращение перехода на профиль)
3. Валидация перед отправкой (проверка currentReceiverId)

## 📝 Примечания

- Сюрпризы отправляются **только при наличии мэтча**
- Анекдоты не повторяются **для каждого конкретного получателя**
- Разные отправители могут отправить один и тот же анекдот одному получателю
- Анимация шампанского показывается только отправителю (локально)
- Сообщения с сюрпризами сохраняются в БД и видны в истории чата
